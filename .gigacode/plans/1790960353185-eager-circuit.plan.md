## 1. Architecture: MVVM + Clean Architecture

### Decision Summary
- **Architecture:** MVVM (not MVI) — better balance of clarity and testability for filtering pipelines
- **DI:** Hilt — compile-time safety, seamless Android lifecycle integration
- **Networking:** Retrofit — mature OkHttp integration, MockWebServer for testing
- **Image Loading:** Coil
- **Navigation:** Jetpack Compose Navigation 2.8+
- **Pagination:** Paging 3
- **Background Sync:** WorkManager

### Layered Structure

```
┌─────────────────────────────────────────────┐
│              UI Layer (Compose)              │
│  Screens + ViewModels + Components          │
└──────────────────┬──────────────────────────┘
                   │ StateFlow / SharedFlow
┌──────────────────▼──────────────────────────┐
│           Domain Layer                       │
│  UseCases (GetItems, FilterSkills, etc.)    │
│  Repository Interfaces                       │
│  Domain Models                               │
└──────────────────┬──────────────────────────┘
                   │ Repository interface
┌──────────────────▼──────────────────────────┐
│           Data Layer                         │
│  RepositoryImpl + Mappers + DataSources      │
│  Room DAOs + Retrofit API + Local Entities   │
└──────────────────┬──────────────────────────┘
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
  Retrofit API           Room DB
```

### Data Flow
```
UI → ViewModel (StateFlow) → UseCase → Repository → Room (cache first)
                                              → Network (refresh in background)
                                              → emit fresh data → UI re-composes
```

## 2. Room Database Schema

### Entities (all in `data/local/entity/`)

| Entity | Table | Key Fields | Indexes |
|--------|-------|------------|---------|
| **ItemEntity** | `items` | id, name, classRestriction, level, type, rarity, location, stats(JSON), description, iconUrl, updatedAt | classRestriction, level, type, rarity, location, composite(class+level), composite(class+rarity) |
| **QuestEntity** | `quests` | id, name, npcId(FK), startLevel, reward(JSON), description, type, prerequisites(JSON), progressStatus, updatedAt | type, startLevel, npcId, composite(type+startLevel) |
| **SkillEntity** | `skills` | id, name, classRestriction, level, type, description, cooldown, iconUrl, manaCost, range, updatedAt | classRestriction, level, type, composite(class+type), composite(class+level) |
| **ClassEntity** | `classes` | id, name(unique), race, subClasses(JSON), description, iconUrl, baseStats(JSON), updatedAt | name(unique), race |
| **NpcEntity** | `npcs` | id, name, type, location, description, relatedQuestIds(JSON), iconUrl, updatedAt | name, type, location |

### Caching Strategy: Stale-While-Revalidate
1. Emit cached data immediately (fast path)
2. Fetch fresh data in background
3. Update Room + re-emit (slow path)
4. If network fails → keep stale data visible

## 3. Filtering & Search Algorithm

### Filter Model
```kotlin
data class ItemsFilter(
    val classRestriction: String? = null,
    val minLevel: Int? = null,
    val maxLevel: Int? = null,
    val type: String? = null,
    val rarity: String? = null,
    val location: String? = null,
    val searchQuery: String? = null,
    val sortBy: SortOption = SortOption.NAME_ASC,
    val page: Int = 0,
    val pageSize: Int = 20
)
```

### Reactive Pipeline (ViewModel)
```kotlin
val filterFlow: Flow<ItemsFilter> = combine(
    searchQueryFlow.debounce(300),
    selectedClassFlow,
    selectedLevelRangeFlow,
    selectedTypeFlow,
    selectedRarityFlow,
    sortByFlow
) { /* combine into ItemsFilter */ }

val uiState: StateFlow<ItemsUiState> = filterFlow
    .flatMapLatest { filter -> itemsRepository.getItems(filter) }
    .map { items -> ItemsUiState(items = items, ...) }
    .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), emptyState)
```

### Optimizations
- Debounce search: 300ms
- `flatMapLatest` to cancel stale queries
- Room indexes on all filterable columns
- Paging 3 for infinite scroll
- Lazy image loading with Coil

## 5. Implementation Phases

### Phase 1 — MVP Foundation
1. Add all dependencies (Hilt, Room, Retrofit, Navigation, Coil, Paging 3, WorkManager)
2. Create package structure (feature-based)
3. Setup Hilt DI graph
4. Setup Compose Navigation
5. Create Theme (dark/light with L2 colors)
6. Implement Items entity + DAO + API + Repository + UseCase
7. Items list screen + detail screen
8. Basic filtering (class, level, type, rarity)
9. Room caching (stale-while-revalidate)
10. Bottom navigation bar

### Phase 2 — Feature Expansion
11. Implement Quests, Skills, Classes, NPCs (same pattern as Items)
12. Complex multi-filter system with FilterBottomSheet
13. Search with autocomplete
14. Paging 3 infinite scroll
15. Coil image loading for all icons
16. Compose animations (item enter, shared element transitions)
17. Pull-to-refresh on all lists
18. WorkManager periodic sync

### Phase 3 — Polish & Release
19. Adaptive layouts (phone/tablet)
20. Theme customization settings
21. ProGuard/R8 rules
22. Unit tests for ViewModels + UseCases + Repositories
23. UI tests for critical flows
24. Build variants (debug/release)
25. App icon, splash screen
