# Migration Plan: Lineage2Guide → Kotlin Multiplatform (Android + iOS + Desktop)

## Summary
Миграция Android-only проекта в KMM с использованием:
- **Compose Multiplatform** для UI (Android + iOS + Desktop)
- **SQLDelight** вместо Room
- **Ktor Client** вместо Retrofit
- **Koin Core** для DI в shared модуле

## Новая структура проекта
```
├── app/                    # Android UI (Compose) + MainActivity + SplashActivity
├── shared/                 # Общий код: domain, data (SQLDelight + Ktor), DTOs, mappers
│   ├── commonMain/         # Общий код
│   ├── androidMain/        # Android-specific DB driver, Ktor engine
│   ├── iosMain/            # iOS-specific DB driver, Ktor engine (Darwin)
│   └── desktopMain/        # Desktop-specific DB driver, Ktor engine
├── iosApp/                 # iOS entry point (Xcode project)
├── desktop/                # Desktop Compose app (optional)
└── server/                 # Ktor server (без изменений)
```

## Фазы реализации

### Phase 0: Подготовка
- Создать git branch
- Убедиться что текущий Android build работает

### Phase 1: Структура проекта
**Файлы:**
- `settings.gradle.kts` — добавить `include(":shared")`
- `build.gradle.kts` (root) — добавить плагин `kotlin-multiplatform`
- `gradle/libs.versions.toml` — добавить зависимости: SQLDelight 2.0.2, Ktor Client 3.0.1, kotlinx-serialization, kotlinx-datetime
- `shared/build.gradle.kts` — новый файл, KMP плагин, Android library, SQLDelight плагин, targets: androidTarget, iosArm64, iosSimulatorArm64, iosX64, jvm("desktop")
- `app/build.gradle.kts` — добавить `implementation(project(":shared"))`, удалить Room/Retrofit/Moshi зависимости

### Phase 2: Domain Layer (100% shareable)
**Move to `shared/commonMain`:**
- `domain/model/` — 5 моделей + 6 enums (без изменений)
- `domain/repository/` — 5 интерфейсов (без изменений)
- `domain/usecase/` — 6 use case классов (без изменений)

**Verification:** `./gradlew :shared:compileKotlinMetadata`

### Phase 3: SQLDelight (вместо Room)
**Create `.sq` files in `shared/commonMain/sqldelight/`:**
- `Items.sq` — CREATE TABLE + queries (getItemsByFilter, getCountByFilter, getItemById, etc.)
- `Quests.sq` — CREATE TABLE + queries
- `Skills.sq` — CREATE TABLE + queries
- `Classes.sq` — CREATE TABLE + queries
- `Npcs.sq` — CREATE TABLE + queries

**Create DB setup:**
- `shared/commonMain/kotlin/.../data/local/Lineage2Database.kt` — interface
- `shared/commonMain/kotlin/.../data/local/DriverFactory.kt` — `expect fun createDriver(): SqlDriver`
- `shared/androidMain/kotlin/.../DriverFactory.kt` — `actual` + AndroidSqliteDriver
- `shared/iosMain/kotlin/.../DriverFactory.kt` — `actual` + NativeSqliteDriver
- `shared/desktopMain/kotlin/.../DriverFactory.kt` — `actual` + JdbcSqliteDriver

**Delete from `app/src/main`:**
- `data/local/Lineage2Database.kt` (Room)
- `data/local/entity/` — все 5 Entity файлов
- `data/local/dao/` — все 5 DAO файлов

### Phase 4: Ktor Client (вместо Retrofit)
**Move DTOs to `shared/commonMain`:**
- `data/network/dto/` — все DTO файлы
- **Изменить:** Moshi `@JsonClass`/`@Json` → Kotlinx `@Serializable`/`@SerialName`

**Create Ktor API service:**
- `shared/commonMain/kotlin/.../data/network/Lineage2ApiService.kt` — Ktor client calls
- `shared/commonMain/kotlin/.../data/network/HttpClientFactory.kt` — `expect fun createHttpClient(): HttpClient`
- `shared/androidMain/kotlin/.../HttpClientFactory.kt` — `actual` + OkHttp engine
- `shared/iosMain/kotlin/.../HttpClientFactory.kt` — `actual` + Darwin engine
- `shared/desktopMain/kotlin/.../HttpClientFactory.kt` — `actual` + CIO engine

### Phase 5: Repository Implementations
**Move to `shared/commonMain`:**
- `data/repository/` — 5 RepositoryImpl (заменить Retrofit на Ktor, Room на SQLDelight)
- `data/mapper/` — 5 Mapper классов (без изменений)

**RepositoryImpl pattern:**
```kotlin
class ItemsRepositoryImpl(
    private val apiService: Lineage2ApiService,
    private val database: Lineage2Database
) : ItemsRepository {
    // Use Ktor client + SQLDelight instead of Retrofit + Room
}
```

### Phase 6: DI Setup
**Update `shared/commonMain/kotlin/.../di/`:**
- `AppModule.kt` — Koin Core modules (без Android DSL)
- Использовать `koinApplication { }` вместо `androidApplication { }`

**Update `app/src/main/kotlin/.../di/`:**
- `AppModule.kt` — Android-specific Koin setup, `androidContext()`, `viewModel { }`
- Подключить shared модули через Koin

**Update `Lineage2App.kt`:**
- Инициализация Koin с shared + app модулями

### Phase 7: UI Layer (Android)
**Update `app/src/main/kotlin/.../ui/`:**
- ViewModels — оставить в app (используют shared repository interfaces)
- Screens — обновить для использования shared repository
- Navigation — обновить для Compose Multiplatform
- Theme — оставить в app (Material 3 Compose)
- `ConnectivityChecker.kt` — использовать expect/actual для platform connectivity

### Phase 8: iOS App
**Create Xcode project:**
- `iosApp/` — Xcode project с Compose Multiplatform
- Entry point: `main.swift` → `ComposeUIViewController { AppNavigation() }`
- Link shared framework

### Phase 9: Desktop (опционально)
**Create `desktop/` module:**
- `desktop/build.gradle.kts` — JVM, Ktor client, Compose desktop
- `desktop/src/main/kotlin/Main.kt` — `fun main() { Window { AppNavigation() } }`

## Потенциальные проблемы
1. **Room → SQLDelight migration** — нужно аккуратно перенести все SQL запросы
2. **Moshi → Kotlinx Serialization** — изменить все DTO, особенно `ClassDto.baseStats`
3. **Koin Android DSL** — заменить на Koin Core в shared, Android DSL оставить в app
4. **ViewModel lifecycle** — ViewModels остаются в app модуле, используют shared repository interfaces
5. **Compose Multiplatform для iOS** — требует настройки Xcode проекта, может потребовать дополнительных зависимостей
